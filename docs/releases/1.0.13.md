「App 管理」开关已打开却仍被拒绝时的处理办法 / What to do when App Management is enabled but writes are still refused

- **写入微信被拒绝、而「App 管理」里 WeChatUnrevoke 的开关明明已经打开时，提示里多了一步：选中 WeChatUnrevoke 用 − 移除，再用 + 添加当前这份。** 原因：本应用没有用开发者证书签名，系统的这项授权只认授权时的那一版；更新应用之后，列表里的开关可能仍显示打开，旧授权却不再作数，输入管理员密码也照样被拒。所以**每次更新 WeChatUnrevoke 后，如果开启或还原时被拒绝，请按这一步重新授权一次**。应用内提示与中英文说明都已补上。
- **验证范围请留意：** 这种拒绝没有在我们自己的机器上触发过。依据是一位用户反馈的完整日志（App Store 版微信，输入管理员密码后仍被拒，其余写入条件都正常）和这项授权按签名识别应用的方式，机制部分是推断。按这一步操作后仍被拒绝，请附上诊断报告反馈。
- 其余功能、支持的微信版本和内置补丁库与 1.0.12 相同。

When a write to WeChat is refused although WeChatUnrevoke is already enabled under System Settings → Privacy & Security → App Management, the in-app guidance now adds one step: select WeChatUnrevoke, remove it with −, then add the current copy with +. The app is not signed with a developer certificate, so macOS ties this permission to the exact version that was granted; after an update the switch can still read enabled while the old grant no longer applies, and an administrator password does not get past it. After each update, repeat this step if enabling or restoring is refused. Both READMEs carry the same guidance. Scope of verification: this refusal was not reproduced on our own machines. The change rests on one user's full log (App Store WeChat, refused after the administrator prompt with every other write condition in order) and on how this permission identifies apps by signature, so the mechanism is an inference; if the write is still refused after this step, please report it with the diagnostics report. Everything else, including supported WeChat builds and the bundled patch library, is unchanged from 1.0.12.
