支持微信 4.2.0；签名失败不再中止 / WeChat 4.2.0; signing no longer stops halfway

- 补丁库收录微信 4.2.0：官网版 4.2.0.9 / .12 / .16 / .17 / .52 / .54（Apple Silicon 与 Intel），以及 build 270416（Apple Silicon）。补丁库联网更新，已装旧版的用户联网退出并重开就能拿到，不必为此升级；本版内置的补丁库也已包含这些构建。
- Intel 只有「留提示」方式（消息保留，仍显示撤回提示）。4.2 的补丁点在腾讯官方安装包副本上验证了写入、切换、签名校验和还原；没有收过真实撤回消息，Intel 补丁点没有在 Intel Mac 上运行过。开启后请让人发一条再撤回试试，不对就点「还原微信」，并把「复制诊断」的内容贴到 issue。
- 修复（[#1](https://github.com/zengtianli/WeChatUnrevoke/issues/1)）：个别系统（反馈来自 macOS 14.8.5 Intel）用本机签名身份重签时报 `The specified item could not be found in the keychain`，开启保护就此失败。现在会先把签名钥匙串临时放进搜索列表重试，仍不行就改用 ad-hoc 签名完成；这种情况下，截屏、麦克风、摄像头授权在每次重新开启后要重新允许一次。
- 读不出的签名钥匙串改为挪到旁边保留，不再删除；读取微信构建号不再依赖图形会话。

WeChat 4.2.0 is now in the patch database: website builds 4.2.0.9 / .12 / .16 / .17 / .52 / .54 (Apple Silicon and Intel) and build 270416 (Apple Silicon). The database updates online, so an installed older version picks it up after quitting and reopening while online; this release also bundles it. Intel has the keep-notice mode only. The 4.2 patch points were verified on copies of Tencent's official installers (writing, switching, signature checks and restoring); no real recalled message has been received with them yet and the Intel points have not run on an Intel Mac, so please test one recall after turning protection on, and use Restore WeChat plus Copy diagnostics in an issue if it misbehaves. Fixed ([#1](https://github.com/zengtianli/WeChatUnrevoke/issues/1)): on some systems (reported on macOS 14.8.5, Intel) re-signing with this Mac's identity failed with `The specified item could not be found in the keychain` and protection stopped there. Signing now retries with the signing keychain temporarily on the search list and otherwise finishes with an ad-hoc signature; in that case Screen Recording, Microphone and Camera have to be allowed again after each re-patch. An unreadable signing keychain is now kept aside instead of deleted, and reading the WeChat build no longer needs a graphical session.

macOS 13+ · Apple Silicon + Intel · ad-hoc signed, without Apple Developer ID signing or notarization.
