补丁库更新修复 / Patch database refresh fix

- 修复 #12：微信版本显示「还没收录」时，「重新检查」和 ⌘R 现在会先重新下载补丁库再检查。此前只在启动时下载一次，那次失败、或 App 在补丁库更新前就已开着，就会一直停在「还没收录」。
- App 一直开着时，如果当前微信版本还没收录，每 30 分钟自动重新下载一次补丁库，服务端新增支持后无需重启即可识别。
- 补丁库下载失败时，界面直接显示原因（网络错误、HTTP 状态、响应不是补丁列表等）；复制诊断新增当前使用的补丁库来源、条目数、SHA256 及是否包含当前 build，以及最近一次下载结果。
- 内容修正（条目数不变）也会触发重新检查；并发刷新合并为一次下载；损坏或变少的响应不会覆盖已有补丁库。识别到新版本本身不会写入微信。
- 本版没有新增补丁点或改变引擎判决；4.1.15.55（270135）的支持已于 10 月 22 日随补丁库上线，使用 1.0.14 的用户按 ⌘Q 完全退出再打开即可获取。

Fixes #12: when the WeChat build shows as not yet supported, Check again and Command-R now re-download the patch database before checking. Previously it was downloaded only once at launch, so a failed download, or an app left open since before the database was updated, stayed on "not yet supported". While the build is unsupported, an open app re-downloads the database every 30 minutes, so newly added support is picked up without a restart. A failed download now shows its reason in the window, and copied diagnostics name the patch database in use (source, builds, SHA256, whether it lists this build) and the last download result. Content corrections with the same number of builds also trigger a recheck; concurrent refreshes share one download; broken or shorter responses never replace the existing database. Recognising a new build never writes to WeChat by itself. No patch locations or engine decisions change in this release; support for 4.1.15.55 (270135) has been live in the patch database since October 22, and 1.0.14 users get it by quitting with Command-Q and reopening.
