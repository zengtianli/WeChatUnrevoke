修复启动闪退，支持微信 4.1.15.54 / 4.1.15.22 与 macOS 13 / Launch crash fix, WeChat 4.1.15.54 / 4.1.15.22, macOS 13

- **修复 1.0.11 一打开就闪退。** macOS 15 上的 Apple Silicon 与 Intel 机器都有报告。原因是同一个：菜单在系统创建应用实例之前就被安装。现在改到启动完成之后。依据是与崩溃报告 UUID 一致的发行二进制反汇编；修复后的启动路径有回归测试，但没有在 macOS 15 实机上重跑。
- **新增微信 4.1.15.54（build 270134）和 4.1.15.22（build 270102）的 Apple Silicon 补丁**，防撤回与拦截自动更新都可用。两个版本都用官方安装包的独立副本、在开启 SIP 的 Mac 上跑过开启、体检、严格签名校验和还原，还原后补丁点与原包逐字节一致。真实聊天里的撤回效果仍需要你自己收一条撤回消息确认。
- **最低系统降到 macOS 13**（此前为 macOS 15）。已核对双架构的部署目标与链接；没有 macOS 13 实机，实际表现请反馈。
- **写入微信失败时说明具体原因和对应办法**，不再一律指向「App 管理」：文件属于 root 需要管理员授权、文件被锁定、访问控制规则拒绝、微信还在磁盘映像里，或者以上都正常而系统仍拒绝（这时才是「App 管理」授权）。
- **Intel Mac：首次有可用的微信 4.x 补丁，并且如实显示支持情况。** 此前收录的 4.x 补丁点只有 Apple Silicon 的，Intel Mac 上会照常写入并显示「已开启」，但微信实际运行的是 Intel 代码，撤回照样生效。现在按本机处理器架构判断：4.1.15.54 与 4.1.15.22 提供「留提示」方式的防撤回和拦截自动更新（没有「静默」方式）；其他版本显示「还没收录」并说明原因，不再写入。**Intel 的补丁点来自对官方安装包的静态分析，写入与还原在安装包副本上跑通，但没有在 Intel Mac 上运行过，也没有收过真实撤回消息**——请开启后自己测一条撤回，不对就点「还原微信」并反馈。
- 详情里显示微信完整版本号（如 4.1.15.54）、安装渠道（官网 / App Store）和处理器架构，反馈问题时复制诊断报告即可带上。

Fixes the crash at launch in 1.0.11, reported on macOS 15 for both Apple Silicon and Intel: the menu was installed before the system had created the application instance, and now waits until launch has finished. The cause was established from the released binary matching the crash reports; the fixed launch path has a regression test but was not re-run on a physical macOS 15 machine. Adds Apple Silicon patches for WeChat 4.1.15.54 (build 270134) and 4.1.15.22 (build 270102), verified on copies of the official installers on a Mac with SIP enabled (enable, diagnose, strict signature verification, restore, byte-identical patch points afterwards); recall behaviour in a real chat still needs your own test. Minimum system is now macOS 13 (deployment target and linkage checked for both architectures; not tested on a physical macOS 13 machine). A refused write now names its actual cause and fix — root-owned files, locked files, a deny ACL, a read-only location, or App Management when nothing else explains it. Intel Macs get their first usable WeChat 4.x patches and are now reported truthfully: until now the 4.x patch points on record were Apple Silicon only, and earlier versions wrote them anyway and showed "enabled" while WeChat kept running unchanged Intel code. Support is now judged by this Mac's architecture: 4.1.15.54 and 4.1.15.22 offer keep-tip anti-recall and the update block on Intel (no silent style); other builds say they are not covered and nothing is written. The Intel points come from static analysis of the official installers, with patching and restoring exercised on copies; they were not run on an Intel Mac and no real recalled message was received, so test a recall yourself and use Restore if it misbehaves. Details now show WeChat's full version, install channel and architecture.
