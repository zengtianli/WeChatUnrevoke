# GUI 启动、权限说明与 macOS 13 兼容

2026-10-10；当前源码候选，尚未发布或安装。公开 v1.0.11 (54) ZIP 仍要求 macOS 15。

## 启动崩溃

公开 ZIP 的 SHA256 为 `f3d0a9a2de3a2f91cc40edeaff59a4815cd871a920aaa3b425a27b710e7a20db`。
两片 UUID 与对应用户崩溃报告一致，故障指令如下（地址为去除 ASLR 后的文件虚拟地址）：

| 架构 / 系统 | UUID | 故障与直接前驱 |
|---|---|---|
| arm64 / macOS 15.7.7 | 8F30BA68-FC7B-32D7-9352-03DB5E97C2AD | `0x1000201b8: brk #1`；`0x10001fd6c: cbz x0, 0x1000201b8`，x0 来自 `_NSApp` |
| x86_64 / macOS 15.6.1 | 05B02DD3-C82F-3788-9B5A-A90243AC6895 | `0x10002398b: ud2`；`0x100023412: je 0x10002398b`，rdi 来自 `_NSApp` |

这是同一个 nil 隐式解包故障：`UnrevokeApp.init` → `AppLifecycleUI.install` → `attachMenu` 读取 `NSApp.mainMenu`，而 SwiftUI 尚未创建 NSApplication。对应寄存器为零；并非 Intel 独有的 CPU 指令不兼容，也不是 MainActor executor 的失败路径。

产品接线改为 `@NSApplicationDelegateAdaptor`，在 `applicationDidFinishLaunching` 安装配置和菜单；`App.init` 不接触 AppKit。共享生命周期副本保持原样。API 依据：[NSApp](https://developer.apple.com/documentation/appkit/nsapp)、[NSApplicationDelegateAdaptor](https://developer.apple.com/documentation/swiftui/nsapplicationdelegateadaptor)。

`tests/test_startup.py` 取 v1.0.11 的完整 Sources，并让原 App 构造接受“NSApp 在构造前后均为 nil”的回归约束；旧源码失败，当前源码通过。本次执行机是 macOS 27：旧源码在本机初始化了 AppKit，随后被测试的 precondition 拦住，**没有把这一结果冒称 macOS 15 的 nil trap 实机复现**。macOS 15 根因来自匹配发行片 UUID 的二进制与崩溃寄存器证据。

## 权限

输入报告是 App Store build 269602：`overall=unprotected`、`writable=false`、`entitlements=ok (15 keys)`、更新拦截 `notApplicable`，原始错误为写入 `Resources/wechat.dylib` 被拒绝。

该错误无法单独区分 root 属主/权限、ACL、不可变标记或 App 管理授权。中英错误说明分别列出这些检查；详情明确是“引擎请求管理员授权”。签名权限完整不代表文件可写，管理员授权也不代表已有 App 管理授权。保留原始日志、写后无条件 doctor、拒绝后暂停自动重试的现有流程。

测试仅使用隔离子进程 fixture。实际 App 管理授权、管理员密码、用户原微信的权限修复均未执行。防撤回和更新拦截仍逐项执行，`antiRevokeOnly` 仍视为完成。

## macOS 13

Info.plist 最低版本和工程四个部署目标都为 13.0，中英 README 同步。`defaultScrollAnchor` 在 macOS 14+ 才调用；13 使用 ScrollView 默认顶端布局。

真实 Xcode 27 / SDK 27 Release universal 构建通过，两片 `LC_BUILD_VERSION minos 13.0`；新滚动 API 的导入为 weak external。全部 GUI 源文件经过部署目标 13 的可用性检查，链接仅使用系统框架和 Swift 运行时。arm64 原生和 x86_64 Rosetta 分别运行同一构建的离屏自检，各 9 项检查、5 张绘制，均无可见/关键窗口。

没有 macOS 13.7.8 或原生 Intel 实机验证，也未验证真实聊天撤回。部署、链接与 Rosetta 证据只覆盖这些检查本身。

## 引擎 JSON 接口

GUI 可选解码 `full_version`、`short_version`、`install_channel`，缺失时版本回落原 `build`，渠道显示未知。详情保留独立 Build 行；诊断报告打印三项新字段。`overall` 始终直接取引擎判决。

隔离 fixture 已验证 `4.1.13.11 / build 90001 / appStore` 的显示与旧字段缺失的回落。发布时由集成方合入引擎实际输出；GUI 候选使用公开 ZIP 中未改动的引擎，仅用于候选完整性检查。
